# Резюме, портфоліо та тестове завдання

- [ ] Заголовок: роль + напрямок («Data Analyst · Banking / Risk»).
- [ ] 3–4 рядки підсумку: роки досвіду, домен, стек, головний результат.
- [ ] Кожен пункт досвіду — **дія + метод + результат у цифрах** («Автоматизував звітність у SQL, скоротив підготовку з 3 днів до 3 годин»).
- [ ] Стек: SQL (діалекти), Python (pandas, numpy), BI (Tableau/Looker Studio/Power BI), BigQuery, Excel/Google Sheets.
- [ ] Освіта, курси, сертифікати — коротко.
- [ ] Мови, посилання (LinkedIn, GitHub).
- [ ] Фото не обов'язкове; без зайвих особистих даних (адреса, документи).
- [ ] Ключові слова з вакансії відображені чесно.

## GitHub-портфоліо

- [ ] Профільний README: хто ви, стек, 3 закріплені проєкти.
- [ ] 3–5 якісних проєктів замість 30 навчальних.
- [ ] У кожному: мета, дані, методи, **висновки**, як відтворити, скріншоти/посилання на демо.
- [ ] Дані — лише відкриті або синтетичні (жодних даних роботодавця чи клієнтів).
- [ ] Структура репозиторію: `data/`, `notebooks/`, `src/`, `docs/`, `README.md`, `LICENSE`.
- [ ] Закріпіть найкращі репозиторії, додайте теги й опис.

### Ідеї проєктів для банківського аналітика

1. Аналіз вінтажів і roll rates на синтетичних даних (див. [SQL-тренажер](https://antonemec.github.io/analyst-html-tools/sql-trainer.html)).
2. Дашборд метрик картки: видача, активність, обіг, прострочка.
3. Модель відтоку з поясненням ознак (SHAP) і планом кампанії.
4. Симуляція A/B-тесту: розмір вибірки, потужність, помилки.
5. Звіт «Ринок карткових платежів» на відкритій статистиці НБУ.

## Тестове завдання

1. Перечитайте умову, уточніть невизначеності листом (коротко).
2. Складіть план: дані → перевірка → аналіз → висновки → рекомендації.
3. Робіть відтворюваний результат: ноутбук/скрипт + короткий звіт 1–2 сторінки.
4. Верх звіту — **висновки та рекомендації**, далі методологія.
5. Покажіть обмеження й припущення.
6. Перевірте цифри двічі, нехай колега прочитає.
7. Відправте раніше дедлайну з коротким супровідним листом.
